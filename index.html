1 · Context Length

Cold cache, a fresh prompt each request, context growing 1k → 200k (400k for DeepSeek V4) — the big picture, not a coding-only lens. The two rates that matter per context: prefill (prompt processing tok/s) and generation (decode tok/s). Prefill is where devices diverge most — and it's what dominates real coding/agentic turns (big context, small reply).

6 · What should you actually buy?

The "which hardware" answer, in the units you actually care about: minutes of your day, per machine, per model. Then the $5–8k decision: M5 Ultra or DGX Spark ×2, side by side.

M5 Ultra or DGX Spark ×2

DGX Spark ×2 is the measured 2-node cluster (~$8k); M5 Ultra is the projected Mac Studio (1.2 TB/s, 80-core GPU — $5,499 @ 96 GB, ~$12k @ 256 GB, ~$20k+ @ 512 GB). Four comparisons: decode speed, prompt ingestion, a real agentic turn (50k context, 500-token reply), and a 6-stream batch.

Price reality check: M5 Ultra is $5,499 @ 96 GB, ~$12k @ 256 GB, ~$20k+ @ 512 GB. The 512 GB tier — the one that lets it hold frontier-scale models the 128 GB DGX can't — costs ~2.5x a DGX Spark ×2 cluster (~$8k) or an RTX PRO 6000 box that still beats it on teams and long sessions. The fast-single-user value case only holds at the 96 GB price; the big-memory advantage is real but paid for at a steep premium.

The fine print

What was measured. The warm phase of each run is one contiguous corpus growing 40k→50k in 2k-token turns — a coding session that keeps appending. Session wall-clock is the sum of each turn's measured total_ms. The no-cache estimate re-prices every turn at cold-cache prefill cost for its context length (log–log interpolated from measured cold points) plus the same measured generation time — what the session would've cost if the server forgot the prefix every turn. Multi-user numbers sum the concurrent-batch wall span per warm step.

Caveats. No think-time between turns, so this is the best case for a session. Single runs, so individual cells will wobble. Apple's prefix caching is a config thing, not a hardware limit — Qwen3.6/Qwen3.8 on MLX re-processed every turn here (warm ≈ cold), but DeepSeek V4 on the same Mac did cache (2.6x speedup), so bigger models get more out of it. Power/efficiency figures use the 50k runs since they're long enough to sample cleanly. Qwen3.6/Qwen3.8 single-user numbers are run-averaged across each machine's complete runs (smooths noisy decode); concurrent batches stay on the latest run since streams can't be aligned across runs. Run selection, concurrency math, and repro scripts live in analysis/.

Model quants. Every model ran at the largest quantization that fits its machine, and we standardized the format across machines wherever it fits. The Apple Macs (M5 Max, M3 Ultra) ran MLX quantized weights: 8-bit for the Qwen3.6-35B-A3B MoE, 4-bit for the Qwen3.8-27B dense and for DeepSeek-V4-Flash. The NVIDIA Blackwell boxes (vLLM) ran NVFP4 — NVIDIA's 4-bit float, W4A4, E2M1 values with an FP8 scale per 16-value block — for the dense 27B on all three, and for the 35B MoE on the 32 GB RTX 5090; where memory allows (DGX Spark ×2, RTX PRO 6000) the MoE ran at higher fidelity FP8 (8-bit float). DeepSeek-V4-Flash on the DGX used the official release checkpoint, which already ships quantized at the source — MXFP4 4-bit routed experts with FP8 elsewhere (284B total, 13B active) — and the Mac served a matching 4-bit MLX conversion. Quantization level is thus comparable within a hardware family, but not bit-identical across them; read the absolute rates with that in mind.
